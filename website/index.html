Sqlo 是建立在 node:sqlite 之上的薄封装：一个普通对象 schema 推导全部类型，每一条生成的 SQL 都参数绑定，DDL 只通过显式 sync() 与 migrate() 执行。

为什么是 Sqlo

只做一件事，做得很薄。

不引入 better-sqlite3，不搬运 WASM。用 Node 自带的东西，把类型和安全交给类型系统与参数绑定。

→

Schema 即类型

一个普通对象定义表结构，RowOf / InsertOf / PatchOf 自动推导实体、插入与更新类型。没有装饰器，没有模型类。

// 类型从这里来
const users = db.define({ name: 'users', columns: { … } });
const u = users.insert({ … }); // 完整类型推导
?

参数绑定是默认

生成的每一句 SQL 都用 ? 占位符收集参数，值绝不拼接进字符串。注入不是一条可达的路径。

// 值 → 绑定参数
users.query()
  .where({ age: { gte: 18 } })
  .all();
// … WHERE "age" >= ?   params: [18]
!

DDL 显式，迁移诚实

表只由 sync() 或 SQL 文件迁移创建，永不自动建表、永不自动 diff。SQLite 的 ALTER 限制被如实对待。

const applied = db.migrate(
  loadMigrationsSync('./migrations')
);
// SQL 文件 + 版本表，绝不 diff

用法

从一个对象到一条查询。

三个片段覆盖 Sqlo 的核心工作流——定义、查询、演进。

import { Sqlo, sql } from '@chaeco/sqlo';

const db = new Sqlo({ path: ':memory:' });

// 一个普通对象 —— 类型从这里推导
const users = db.define({
  name: 'users',
  columns: {
    id:    { type: 'INTEGER', primaryKey: true, autoIncrement: true },
    name:  { type: 'TEXT', notNull: true },
    email: { type: 'TEXT', notNull: true },
    age:   { type: 'INTEGER' },
  },
  indexes: [{ name: 'idx_users_email', columns: ['email'], unique: true }],
});

users.sync(); // 显式建表 —— 绝不自动
const alice = users.insert({ name: 'alice', email: 'a@x.io', age: 30 });
// ^? { id: number; name: string; email: string; age: number | null }
import { sql } from '@chaeco/sqlo';

// 流式构造器 —— 每一条 SQL 都参数绑定
const adults = users
  .query()
  .where({ age: { gte: 18 } })
  .orWhere({ name: { like: 'admin%' } })
  .orderBy('age', 'DESC')
  .limit(10)
  .all();

// 联表 —— ON 子句是 sql 片段
const rows = posts
  .query()
  .join('users', sql`users.id = posts.userId`)
  .select('posts.title', 'users.name')
  .all();

// 安全组合 —— 值绑定，标识符加引号
const q = sql`SELECT * FROM users WHERE email = ${email}`;
// → '… WHERE email = ?'   params: [email]
import { schemaDiff, generateMigrationSql } from '@chaeco/sqlo';

// 演进不靠自动 diff —— 而是差异分析 + 你审查后的 SQL 迁移
const actual   = reflectTableSchema(db, 'users');   // 数据库里真实的表
const desired  = { … };                          // 代码里想要的表

const diff = schemaDiff(actual, desired);
// addedColumns → ['email']
// statements   → 'ALTER TABLE "users" ADD COLUMN "email" TEXT;'

// 生成可保存的迁移 SQL 文件
const sqlFile = generateMigrationSql(actual, desired);

诚实的边界

知道它不做什么，比知道它做什么更重要。

同步优先，异步如实

同步 API 是默认且从不隐藏。可选的 AsyncSqlo 用 worker 线程避免事件循环阻塞，但底层 SQLite 仍是同步、单写者——不假装并发。

仅 SQLite

没有跨数据库抽象层，不模拟 SQLite 不具备的能力。换个库就是换一个工具，而不是一层适配器。

显式迁移

SQLite 的 ALTER TABLE 支持有限。Sqlo 用 SQL 文件迁移 + 版本表，从不自动 diff——因为自动 diff 有数据丢失的风险。

最小范围

Schema、模型、查询构造器、类型映射、迁移。没有缓存、没有连接池、没有事件钩子。少即是稳定。
